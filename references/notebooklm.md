# NotebookLM в курсе

Читать до этапа 2 (раздел «Поиск источников»), до этапа 4 (весь файл) и перед любым запросом к блокноту во время учёбы.

## Зачем

NotebookLM — блокнот Google, который отвечает только по загруженным в него источникам и показывает цитаты. Бесплатный, нужен Google-аккаунт. В курсе у него три работы:

1. **Проверка уроков.** Урок пишет модель, а модель иногда уверенно ошибается. Блокнот находит в уроке утверждения, которых нет в источниках.
2. **Первая ступень подсказки.** Человек не понял понятие — вопрос к блокноту. Ответ приходит с цитатой из первоисточника, а не из памяти модели.
3. **Второй канал поиска.** Встроенный поиск источников (Deep Research) находит то, что пропустил Claude.

Плюс по желанию — квизы, карточки, аудиообзор для дороги. Расписание повторов при этом ведёт `queue.md`, а не блокнот.

**Название.** В 2026 году Google переименовал NotebookLM в Gemini Notebook. Если человек не находит сервис по имени — поискать текущее название и адрес. В текстах курса — NotebookLM.

## Режим по умолчанию — ручной

Claude готовит файл и точный текст запроса. Человек загружает и спрашивает в браузере, ответ вставляет в чат. Каждый запрос выдаётся отдельным блоком кода, чтобы его можно было скопировать одним движением.

**Почему не автоматизация.** У обычных аккаунтов нет официального API: Google даёт его только корпоративным клиентам через Google Cloud. Сторонние инструменты работают через куки браузера и недокументированные запросы: ломаются без предупреждения и могут привести к ограничениям аккаунта. Человек всё равно хочет автоматизацию — только на отдельном учебном Google-аккаунте, после чтения кода инструмента, его решением. **[по документации: не проверялось]**

## Настройка (этап 4)

1. Создать блокнот с названием курса.
2. Загрузить источники модуля 1 — по колонке «в блокнот» в `sources.md`. Блокнот принимает PDF, ссылки на сайты, видео YouTube, Google Docs, вставленный текст. Если источник не загрузился, например сайт закрыт для робота, — скачать PDF или вставить текстом.
3. **Только то, что человек видел сам.** На тему — один главный источник, остальное — справочник.
4. **Не загружать синтез курса:** `program.md`, `method.md`, `research.md`, файлы кейса. Уроки частично написаны по ним, и проверка урока по ним же была бы замкнутой.
5. Записать в `notebook.md`: название блокнота, что загружено, когда.

Перед первым уроком каждого модуля — одной строкой напомнить загрузить его источники.

## Запросы

Копировать как есть, подставив значения в `<>`.

### Поиск источников (этап 2)

Запускать в режиме Deep Research, если он есть, иначе — обычным поиском источников в блокноте:

```
Найди лучшие источники по теме «<тема>» для самостоятельного курса уровня <уровень>. Цели ученика: <2–3 цели из брифа>. Нужны стандарты и своды знаний области, первоисточники авторов основных методов, официальные руководства и документация, рецензируемые обзоры, сильные практические руководства. Пропусти рекламные статьи и пересказы без ссылок. Для каждого источника: название, автор или организация, год, ссылка, чем полезен.
```

Человек присылает список. Найденное **не** добавляется в блокнот сразу: сначала доверие и проверка по `references/research.md`.

### Проверка урока

1. Загрузить файл урока как источник. **Только урок, без эталона** — эталон лежит в `_course/keys/`, и показывать его блокноту незачем.
2. Запрос:

```
Найди в документе «<имя файла урока>» утверждения, которые не подтверждаются другими источниками блокнота. Для каждого: цитата из урока, что говорят источники, есть ли противоречие.
```

3. Ответ человек приносит в следующую сессию. Claude исправляет урок; правка — строкой в `log.md`.
4. Исправленный урок можно убрать из блокнота, чтобы не засорять его, или оставить для квизов.

### Непонятное понятие (подсказка 1)

```
Объясни «<понятие>» по источникам блокнота: определение, пример, чем отличается от «<соседнее понятие>». Укажи, из каких источников это взято.
```

### Квизы и карточки — по желанию

Встроенные квизы и карточки по источникам модуля. Это самопроверка между сессиями, учёт ведёт `queue.md`.

## Без NotebookLM

Нет Google-аккаунта или человек не хочет. Тогда:

- **Проверка урока** — Claude сверяет урок с локальными файлами источников в `materials/`: для каждого утверждения с меткой найти место в источнике. Сказать прямо, что это слабее: проверяет та же модель, что писала.
- **Подсказка 1** — цитата из локального файла источника вместо запроса к блокноту.
- **Поиск источников** — только каналы Claude и материалы человека.

## Проверка перед выдачей

- [ ] каждый запрос выдан отдельным блоком кода, с подставленными значениями
- [ ] в блокнот уходит только просмотренное человеком; синтез курса не загружается
- [ ] урок на проверку уходит без эталона
- [ ] `notebook.md` обновлён: что загружено, какие проверки прошли
