# Ретро курса и отзыв о скилле

Читать перед командами «ретро» и «отзыв».

Две разные вещи. **Ретро** улучшает курс человека: программу, источники, темп. **Отзыв** улучшает сам скилл для всех: это issue в публичном репозитории.

## Ретро

Когда: каждые 8 сессий или после закрытия модуля. Скилл предлагает одной строкой, человек может отказаться. Займёт 10–15 минут.

1. **Цифры** — из `state.md`, `log.md`, `queue.md`, `notebook.md`, `sources.md`, `field/seeds.md`:
   - тренд подсказок: на урок и на упражнение, по модулям;
   - доля верных ответов на припоминании и повторах по модулям;
   - тесты и долги;
   - уроки, где NotebookLM нашёл утверждения без опоры, — на каком источнике они стояли;
   - источники, которые ни разу не понадобились;
   - семена, которые лежат без дела, и отдача источников поля.
2. **Три вопроса человеку:**
   - что было полезнее всего;
   - что было лишним или раздражало;
   - где было непонятно, что делать.
3. **Не больше трёх изменений,** каждое — «вместо», а не «плюс»: заменить слабый источник, поменять порядок уроков, сократить теорию в пользу практики, сменить мёртвый канал поля. Предложить, объяснить цену. Решает человек.
4. **Запись** — в `_course/retro.md`: дата, цифры, ответы человека, принятые решения. Изменения программы — по разделу «Изменения» из `references/design.md`.
5. Проблема не в курсе, а в самом скилле — шаг непонятен, правило мешает, скрипт ломается — предложить «отзыв».

## Отзыв

Человек пишет «отзыв», или в ретро выяснилось, что проблема в скилле.

1. **Спросить:**
   - на каком этапе или команде случилось;
   - что ожидал;
   - что получилось;
   - как повторить, если понятно.
2. **Добавить контекст сам:**
   - версия скилла из `SKILL.md`, раздел «Об авторе»;
   - этап или модуль из `build.md` или `state.md`;
   - операционная система;
   - какие поисковые инструменты есть.

   Тему курса — только если человек разрешил.
3. **Вычистить личное.** Без содержимого брифа, имён, работодателя, ключей API, путей с именем пользователя (домашнюю папку — как `~`). Цитату ответа Claude — только если человек сам её выбрал.
4. **Показать черновик целиком:**

   ```
   Заголовок: <этап>: <что не так одной фразой>

   **Этап / команда:** …
   **Что ожидал:** …
   **Что получилось:** …
   **Как повторить:** …
   **Окружение:** course-builder <версия>, Claude Code, <ОС>, поиск: <инструменты>
   **Тема курса:** <если разрешено>
   ```

5. **Публикация — только после явного «да»:** issue публичный, его увидят все.
   - Есть `gh` и он авторизован (`gh auth status`) — создать: `gh issue create --repo kaspruknikita-tech/course-builder --title "<заголовок>" --body-file <файл с текстом>`. Дать ссылку на созданный issue.
   - Нет — дать ссылку `https://github.com/kaspruknikita-tech/course-builder/issues/new` и текст для вставки.

## Проверка перед выдачей

- [ ] ретро: цифры посчитаны из файлов, а не по памяти; изменений не больше трёх, каждое «вместо»
- [ ] ретро: решения записаны в `retro.md`, изменения программы — по правилам design.md
- [ ] отзыв: в тексте нет личных данных, ключей, путей с именем пользователя
- [ ] отзыв: черновик показан, опубликован только после «да»
