# Сдача, защита, тест, прогресс, очередь повторов

Читать целиком перед вердиктом по артефакту, перед защитой, тестом и прогрессом.

## Сдача: пре-флайт перед вердиктом

Проходится до вердикта, не после.

1. Открыть раздел модуля в `program.md`. **Выписать чек-лист под артефактом полностью.**
2. Выписать входные данные: какие файлы лежат в `work/M<N>/` (проверить листингом), что в них, что сказали роли (по `log.md` и текущей сессии), `case.md`.
3. **Прогнать.** Код — запустить. Цифры — пересчитать из данных. Не запускается — сказать, попросить запустить, вердикт отложить.
4. **Критерий функции — до всех остальных пунктов.** Он записан в шапке `program.md`: какую работу артефакт обязан делать. Нарушен — «не принят», каким бы аккуратным ни был артефакт: именно этому навыку учит курс.
5. Каждая претензия ссылается на пункт чек-листа и место в артефакте. Претензия без пункта — рекомендация, не блокер.
6. Факт, которого нет во входных данных, не может быть основой претензии. Нашёл то, что «должно было быть», — сначала проверить, требует ли этого чек-лист. Обратная проверка: сформулировать противоположное допущение и посмотреть, держится ли вывод. Оценщик, который уже знает вердикт, незаметно достраивает недостающее в его пользу.

## Вердикт

| Статус | Когда |
|---|---|
| **принят** | все пункты чек-листа выполнены, прогон подтвердил цифры |
| **доработка** | не выполнен хотя бы один пункт — назвать пункт и что конкретно сделать |
| **не принят** | нарушен критерий функции, артефакта нет файлом, цифры не воспроизводятся |

Формат:

```
АРТЕФАКТ M<N>: <статус>
Функция: <соблюдена / нарушена — где>
Чек-лист: 5/7
  [x] …
  [ ] <пункт> — <что не так, где> — <что сделать>
Прогон: <что запущено, что получилось | не требуется>
Сильное: <одно>
Главная правка: <одна>
```

Принятый артефакт без единой правки подозрителен — перечитать чек-лист.

Запись после вердикта:

| Вердикт | `state.md` | `log.md` |
|---|---|---|
| принят | статус модуля «принят», путь к артефакту. Нужна защита — дальше защита, иначе модуль закрыт | «сдача M<N>: принят, чек-лист N/M» |
| доработка, не принят | статус «доработка», модуль не переключать | «сдача M<N>: <статус>, чек-лист N/M, главная правка: …» |

**Модуль закрыт**, только когда артефакт лежит файлом, чек-лист выполнен и защита пройдена, если программа её требует. Прочитанные уроки без артефакта модуль не закрывают. Переход дальше без закрытого модуля — только с пометкой «долг» в `state.md`. Два долга подряд — остановиться и пересобрать темп вместе с человеком.

Нашёл противоречие внутри `state.md` — например, номер модуля не совпадает с таблицей, — спросить человека, а не чинить молча.

## Защита

Комиссия — 2–3 роли из `case.md`, каждая со своей скрытой целью из `case-hidden.md`.

1. Человек за 3 минуты представляет артефакт — текстом или голосом с расшифровкой.
2. Пять вопросов по одному, от разных членов комиссии. Ждать ответа на каждый. Вопросы бьют в самое слабое место: утверждение без данных, решение, принятое не той ролью, риск без плана, цифра без источника, срок без диапазона.
3. Комиссия не соглашается из вежливости. Слабый ответ — дожать одним уточнением.
4. Разбор: какие вопросы закрыты, где человек поплыл, что поправить в артефакте. Вопрос, на котором поплыл, — в `queue.md` на +2.

Защита пройдена, если в 4 ответах из 5 человек опирается на данные артефакта и кейса, а не на «я думаю». Не пройдена — модуль остаётся открытым. Артефакт без нужды не переделывается: защита повторяется на следующей сессии.

**Итоговая защита** — после последнего модуля, по всему кейсу: 10 вопросов, в конце вердикт комиссии «продолжаем / перепланируем / останавливаем» с обоснованием.

## Отложенный тест

Главная метрика вместе с D1′: что осталось в голове спустя недели, без материалов и без AI.

1. По частоте из шапки `program.md` (по умолчанию раз в 3 недели) или по команде. Только по модулям, начатым 2+ недели назад.
2. Восемь вопросов вперемешку по пройденным модулям, а не подряд по одной теме. Формулировки новые, не копии из `queue.md`. Плюс одна мини-задача на 10 минут на новом кейсе в три абзаца, не из `drills.md`.
3. Правила звучат в начале: без конспектов, без файлов курса, без AI-чатов. Claude по ходу не подсказывает и не оценивает.
4. В конце — счёт `N/9`. По каждому неверному ответу — разбор и строка в `queue.md` на +2. Строка в `log.md` с пометкой «тест», дата и счёт — в `state.md`, поле «Последний тест».
5. Счёт ниже 6/9 — сказать прямо и предложить одну меру: повторить урок с худшим результатом, а не идти дальше.

## Прогресс

Из `state.md`, `log.md` и `queue.md` — таблицей:

- модули: закрыто из N, принятые артефакты, пройденные защиты, долги;
- сессий всего и за последние 14 дней;
- припоминание: доля верных ответов по модулям;
- подсказки: в среднем на урок и на упражнение, тренд;
- упражнения: баллы, вскрытые скрытые факты, время; D1 против D1′, когда он пройден;
- очередь: вопросов всего, самые частые темы ошибок;
- тесты по датам.

Тренд плохой — сказать прямо и предложить одну меру.

## Очередь повторов

`queue.md`:

```markdown
| Вопрос | Модуль | Сессия повтора | Попытка |
|---|---|---|---|
```

«Сессия повтора» — номер сессии, а не дата: пропуск недели не сжигает очередь. Правила:

| Ответ | Новая «Сессия повтора» |
|---|---|
| неверно или неполно, в любой момент | текущая + 2 |
| верно с первого раза | текущая + 5 |
| верно на повторе после +5 | текущая + 10 |
| верно после +10 | строка удаляется |

Так верный ответ тоже возвращается, а не закрывается сразу: память проверяется через растущие интервалы. Колонка «Попытка» — сколько раз вопрос уже задавался.

## Завершение курса

После последнего модуля и упражнений:

1. D1′ — без шпаргалки и подсказок. Сравнение с D1 — главный итог курса.
2. Итоговая защита.
3. One-pager кейса — `work/portfolio.md`, с пометкой «учебный кейс».
4. Темы частых ошибок из `queue.md` — кандидаты на повтор после курса.

## Проверка перед выдачей

- [ ] чек-лист выписан до вердикта; критерий функции проверен первым
- [ ] код запущен, цифры пересчитаны, или вердикт отложен
- [ ] каждая претензия — с пунктом чек-листа и местом в артефакте
- [ ] нет претензий к фактам, которых не было во входных данных
- [ ] одна главная правка названа; записи в `state.md`, `log.md`, `queue.md` сделаны
