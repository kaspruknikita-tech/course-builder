# Поле: где практики говорят о теме и что оттуда брать

Читать на этапе 2 после канона, перед командой «обнови поле» и когда для упражнения, события или теста нужна свежая ситуация.

Канон отвечает, **как правильно**. Поле — **как бывает на самом деле**: какие ситуации случаются, о чём спрашивают, где спорят, что советуют читать. Курс на одном каноне учит по учебнику и проверяет на выдуманных задачах. Курс с полем тренирует на ситуациях, которые человек встретит в работе, и знает, какие темы у практиков болят сильнее всего.

Ничего не зашито под профессию. Для каждого курса источники поля находятся заново: у DevOps это постмортемы и r/sre, у саппорта — истории из поддержки и r/CustomerSuccess, у UX — ux.stackexchange и разборы исследований. Процедура одна.

Файлы поля — в `_course/field/`: `sources.md` (откуда брать), `vocab.txt` (словарь темы), `seeds.md` (банк семян), `raw/` (сырьё, Claude его не читает), `seen.json`. Сборщик — `scripts/field.py` из этого скилла, чистый Python без установки пакетов.

## 1. Где обычно разговаривают практики

Типы мест, а не адреса: адреса находятся поиском под тему и проверяются.

| Тип места | Что там ценного | Как найти | Тип в `sources.md` |
|---|---|---|---|
| Reddit — сабреддиты профессии | ситуации от первого лица, вопросы «что бы вы сделали», споры | `field.py find-reddit <префиксы>`; поиск `site:reddit.com <тема>` | `reddit` |
| Stack Exchange — сайты по теме | канонические вопросы практиков с голосами | `field.py find-se <слова>` | `stackexchange` (сайт или сайт:тег) |
| Telegram — публичные каналы | живая практика на языке ученика, разборы, кейсы | запросы: `awesome <тема> telegram`, `подборка телеграм каналов <тема>`, `лучшие telegram каналы для <профессия>`, каталоги каналов | `telegram` |
| Hacker News | технические темы: разборы, Ask HN | запрос, а не адрес: `postmortem`, `on-call` | `hn` |
| Блоги и хабы через RSS | разборы, постмортемы, статьи практиков | хабы Хабра (`habr.com/ru/rss/hubs/<хаб>/articles/`), теги dev.to (`dev.to/feed/tag/<тег>`) и Medium (`medium.com/feed/tag/<тег>`), инженерные блоги компаний | `rss` |
| Медиа и платформы историй без ленты по теме: vc.ru, Пикабу, DTF, Т—Ж, Medium, Substack и им подобные | истории «как мы…», провалы, разборы решений от первого лица — особенно бизнес, продукт, маркетинг, сервис, найм | поисковые запросы к домену: `site:vc.ru <тема> кейс`, `site:vc.ru <тема> как мы`, `site:<домен> <тема> ошибки` | `поиск` — читает Claude, не скрипт |
| Подборки постмортемов, кейсов, историй | готовые ситуации высокого качества | `<тема> postmortem collection`, `<тема> case studies`, `<тема> war stories`, `lessons learned <тема>`, `awesome <тема>` на GitHub | `rss` или вручную в `seeds.md` |
| Сообщества человека | то, что он сам читает | вопрос в интервью | любой подходящий тип |

Закрытые чаты, Discord и Slack-сообщества сборщик не читает. Человек может принести оттуда истории сам — тогда они идут в банк вручную, без имён.

Для каждого места искать на двух языках: на языке курса и на английском, если человек читает по-английски. Поле на одном языке беднее.

## 2. Найти и проверить источники

1. Из брифа выписать профессию, 3–5 ключевых тем и типичные ситуации, в которых работает человек этой профессии. Ситуации — подсказка для поиска и для словаря.
2. По таблице раздела 1 найти кандидатов: 2–5 сабреддитов, 1–3 сайта Stack Exchange, если есть по теме, 3–8 Telegram-каналов, 1–3 запроса к HN, если тема техническая, 2–5 RSS-лент.
3. Отсеять сразу:
   - каналы вакансий и объявлений;
   - чисто новостные ленты без разборов;
   - сабреддиты-тёзки, которые совпали только по префиксу;
   - каналы-агрегаторы ссылок без текста.
4. Записать кандидатов в `_course/field/sources.md` и проверить:

   ```bash
   python3 <путь к скиллу>/scripts/field.py check <папка курса>/_course/field
   ```

   «Нет пригодных постов» — значит, канал мёртв или в нём нет текста, только медиа или ссылки. Такой источник получает статус «выбыл» с причиной. Ошибка — проверить адрес.
5. Мало живых источников — честно сказать, что поле по теме бедное, и усилить канал «подборки кейсов» и сообщества человека. Не набивать поле случайными каналами ради числа.

## 3. Словарь темы

`_course/field/vocab.txt` — 30–80 строк: основы ключевых слов темы на языке курса и на английском, по одной на строку. Используй основы, а не полные слова: `инцидент`, `эскалац`, `deploy`, `churn`. Строки с `#` — комментарии.

Словарь отсекает посты не по теме. Он собирается из ключевых тем брифа, терминов канона и типичных ситуаций профессии. Слишком общие слова — «работа», «проект», «user» — тянут шум, их не брать.

### Источники типа `поиск`

У многих площадок нет ленты по теме и открытого API. Тогда источник — поисковый запрос, а не адрес. В `sources.md` тип `поиск`, в «Адресе» — запрос: `site:vc.ru служба поддержки кейс`. Скрипт такие строки пропускает. Claude выполняет запрос своим поисковым инструментом, открывает 3–10 лучших материалов и берёт из них семена по правилам раздела 5. Читать саму страницу, а не только сниппет: развилка и факты обычно в середине текста. Внутренние API площадок без документации не использовать: они ломаются без предупреждения и могут нарушать правила площадки.

## 4. Сбор и выжимка

При сборке курса — окно за год:

```bash
python3 <путь к скиллу>/scripts/field.py harvest <папка курса>/_course/field --days 365
```

Потом, по команде «обнови поле», — свежее: `--days 30`. Сбор идёт 1–3 минуты, сырьё ложится в `raw/<дата>.json`. **Сырой JSON не открывать:** файлы большие, а выжимка делает то же за малую долю токенов:

```bash
python3 <путь к скиллу>/scripts/field.py digest <папка курса>/_course/field --top 30
```

Выжимка берёт сырьё новее строки «Последнее обновление банка» в `seeds.md`. Она отсекает вакансии и рекламу, оставляет посты со словами из словаря, помечает тип: вопрос, ситуация, спор, совет. Сортирует по совпадению с темой и отклику и выводит не больше трети записей из одного источника.

## 5. Отбор семян

Из выжимки — 8–20 семян при сборке и 3–8 при обновлении. Семя — не пост, а то, что из него берётся:

| Тип семени | Что записать | Куда идёт в курсе |
|---|---|---|
| **ситуация** | механика своими словами, факты-якоря (цифры, сроки, ограничения), развилка решения | брифы упражнений, скрытые факты и события кейса, мини-задачи теста |
| **вопрос** | что спрашивают и почему это трудно | вопросы попытки, вес темы в программе |
| **спор** | две позиции и на чём они стоят | шаг «критика» в уроке, вопрос защиты |
| **совет** | что практики советуют читать или каким инструментом пользоваться, сколько раз встретилось | кандидат в источники. Это сырьё: найти первоисточник и пройти проверку по `references/research.md` |

Правила отбора:

- **Ситуация годится,** если в ней есть ставка, ограничение и развилка. Мнение, анонс, «10 советов» — не ситуация.
- **Своими словами.** Текст поста в банк не копировать. Автор и его ник не записываются, только ссылка.
- **Домен и цифры подменяются,** когда семя превращается в бриф: механика та же, компания, отрасль и числа — другие. Иначе человек может узнать историю и вспомнить ответ, а не решить задачу.
- **Разнообразие.** Не больше трети семян банка из одного источника. Знакомая ситуация тренирует память, а не навык.
- **Семя — сценарий, а не доказательство.** Пост одного человека не подтверждает, что «так делают все». Факты урока по-прежнему берутся только из канона.

Банк — `_course/field/seeds.md`: ID, тип, суть своими словами, факты-якоря, развилка, тема или модуль, источник (URL), использован (дата и где). После отбора — обновить строку «Последнее обновление банка» датой самого свежего разобранного файла сырья.

## 6. Карта боли поля

После первого отбора — короткая таблица в `_course/research.md`: темы поля по частоте (сколько семян и постов в выжимке) против тем программы. Её видят на этапе 3:

- тема горячая в поле, но в программе её нет или она в конце — кандидат подвинуть или добавить вместо другой;
- тема есть в программе, но в поле о ней молчат — это может быть основа, о которой не спорят, а может быть устаревшая тема. Проверить по канону.

Решает человек.

## 7. Обновление во время учёбы

Команда «обнови поле» — по умолчанию раз в месяц, скилл напоминает одной строкой:

1. `harvest --days 30`, затем `digest`.
2. 3–8 новых семян в банк.
3. Свежие ситуации — в ближайшие упражнения и события, свежие вопросы — в попытки.
4. Отдача источников:

   ```bash
   python3 <путь к скиллу>/scripts/field.py yield <папка курса>/_course/field
   ```

   Источник без семян после трёх разобранных сборов — «кандидат на удаление». Одной строкой предложить человеку заменить его новым.

## 8. Ограничения и этика

- Читаются только **публичные** страницы, без входа в аккаунт. Сборщик делает паузы между запросами и не ходит чаще, чем нужно курсу.
- Reddit читается через публичный архив arctic-shift: собственный JSON Reddit без авторизации закрыт. Архив может быть недоступен — тогда сборщик пишет ошибку, остальные источники собираются. Запасной путь — поиск `site:reddit.com <тема>` поисковым инструментом.
- Stack Exchange без ключа даёт около 300 запросов в день — курсу хватает с запасом.
- Люди в постах реальные. В банк — только механика и ссылка, без имён, ников и деталей, по которым человека можно узнать.

## Проверка перед выдачей

- [ ] источники найдены под эту тему поиском, а не взяты из памяти; все прошли `check`
- [ ] вакансии, новостные ленты и мёртвые каналы отсеяны или помечены «выбыл»
- [ ] словарь — основы слов темы на двух языках, без слишком общих слов
- [ ] сырой JSON не открывался, работа шла по выжимке
- [ ] семена своими словами, без имён, со ссылкой; не больше трети из одного источника
- [ ] карта боли поля записана в `research.md`; дата банка обновлена
